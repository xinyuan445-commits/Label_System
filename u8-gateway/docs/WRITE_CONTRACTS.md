# 新增与修改字段规则

## 当前结论

9 类单据已经建立第一版写入策略，来源包括 U8 16.0 原生 XML、888 只读样例和旧 COM 项目中材料出库、盘点的已用赋值逻辑。策略状态仍是 `candidate`；委外到货是 `deferred-candidate`。这些状态只表示规则可以进入无写入测试，不表示已经允许写账套。

材料出库已接通候选新增运行时，当前 Business API 测试业务能够通过表头、表体和货位的无写入合同校验。`create` 能力仍为 `false`；只有完成 888 最小蓝字新增、回读、标签事务提交、已知失败和结果不明场景验收后才能调整能力开关。红字、托盘和自动审核不在本轮开放范围。

全部 U8 写能力和服务器测试写入开关继续关闭。每种单据必须在 888 完成新增、修改和回读核对后，才能单独开启能力。

## 字段合同

完整 XML 字段仍保存在各单据合同中。`write-policies.json` 只维护需要人工判断的写入差异，服务启动时合并到 schema：

- `requiredMode=create`：新增最终必须有值；服务端默认值也可以满足必填；
- `requiredMode=conditional`：由存货、仓库、来源单据等条件决定，必须由单据适配器结合 U8 基础资料校验；
- `createWritable`：新增时允许调用方提交；
- `updateWritable`：修改时允许调用方覆盖；
- `clearable`：PATCH 显式传 `null` 时允许清空；
- `defaultValue`：固定服务端默认值；
- `defaultRule`：`today`、`now`、`operatorName`、`operatorId` 或 `rowNumber`；
- `valueSource`：调用方、服务端默认或 U8 匹配键。

没有进入写入白名单的字段默认只读。ID、审核人、审核日期、制单/修改时间、时间戳、工作流状态、记账状态、打印次数和展示名称不得由客户端伪造。

## 校验接口

无写入校验不调用 U8 保存接口：

```text
POST /api/v1/documents/{type}/validate?operation=add
POST /api/v1/documents/{type}/validate?operation=edit
```

校验包括字段是否存在、读写权限、固定必填、默认值、类型、长度、小数位、能否清空、PATCH 行动作和匹配键。校验通过会返回应用默认值后的 `payload`；失败返回 `DOCUMENT_VALIDATION_FAILED` 和带路径的错误列表。

批次、自由项、货位、来源单据、库存和上下游状态属于 U8 数据相关规则，字段合同先记录 `requiredWhen`，后续由每种单据适配器查询当前账套后校验。

## PATCH 与 XML 合并

表头只覆盖明确传入且 `updateWritable=true` 的字段。`lines` 和 `positions` 的每条变更使用 `_action`：

```json
{
  "lines": [
    { "autoid": 1001, "iquantity": 12.5 },
    { "_action": "add", "cinvcode": "01001", "iquantity": 2 },
    { "_action": "delete", "autoid": 1003 }
  ]
}
```

- `_action` 允许 `add`、`update`、`delete`，省略时按 `update`；
- 更新和删除必须带 schema 中 `writeScopes.matchKeys` 指定的稳定键，优先使用 U8 明细 `autoid`；
- 新增行不能提交 U8 生成的 ID，行号缺省时接在原单最大行号之后；
- 未提交的表头字段和原明细行保持原值；
- 显式 `null` 只对 `clearable=true` 的字段生效；
- 修改以 U8 `Load` 返回的原生 XML 为底稿，不重新构造原单；
- 原 XML 的 schema、ID、时间戳、审核状态和未知业务属性全部保留；
- 修改、新增、删除行分别写入 ADO `editprop=M/A/D`；
- 保存前仍要比对 `expectedVersion`，保存后必须重新读取目标字段确认结果。

## 888 验收顺序

1. 仅调用校验接口和 XML 合并自动测试，不写 U8。
2. 对每类单据准备最小新增请求，在 888 开启单类测试能力。
3. 新增后按 ID 和单号回读，核对表头、全部明细、货位和状态。
4. 对可修改字段分组执行 PATCH，回读确认未提交字段没有变化。
5. 验证必填、条件必填、只读、清空、并发版本冲突和失败回滚。
6. 记录证据后再调整字段合同状态和能力开关。

008 始终只读，不参与写入验收。
