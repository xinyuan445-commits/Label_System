# 2026-11-06 盘点关联出入库审核修复

## 改动与边界

盘点开启“上传自动审核”时，先审核盘点单，再审核U8为它生成的其他出库、其他入库单，全部回查已审核才确认成功。未开启时仍只保存未审核盘点单，不自动审核关联单。页面和用户保存的三个开关均未改。

关联条件来自888真实数据：`cSource=盘点`、`cBusCode=CheckVouch.cCVCode`，同时匹配盘点仓库。本次生成单明细的`iCheckIds`为空，不能据它找关联。不按日期、物料、备注或相邻单号猜单。根据盘点行实盘与账面的正负差异判断应生成的方向；只有盘盈不要求其他出库，只有盘亏不要求其他入库，无差异允许没有关联单。按其他出库、其他入库顺序处理全部关联单。

原问题有两处：只审核盘点主单；恢复时主单已审核便直接返回成功。现在主单已审核也继续回查关联单并补审，已审核部分跳过。缺少应有的关联单、原生审核拒绝或最终状态未全部确认均不报成功。明确拒绝保留`PENDING_APPROVAL/FAILED`，结果未知保留`NEEDS_RECONCILIATION/FAILED`，沿原业务组重试；这两种失败状态都传内部`countApprovalRecovery`，主单已审核时才可跳过旧父单版本。普通请求继续校验版本，不扩大弃审或008能力。

复用现有审核凭证、业务状态和USERPCO审核调用；没有新增接口、表、迁移或开关。审核不重新保存盘点、不再次生成本地/旧追溯数量事件，不直接SQL修改U8数量或审核人。
