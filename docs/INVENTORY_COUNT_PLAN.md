# 盘点单实施方案

快速查看已支持能力、限制、操作与验收状态，进入[盘点功能档案](features/盘点单.md)；本方案保留详细实施及后续ERP边界。

资料复核：2026-11-05；H5 dev.95、API0.12.11 / Gateway0.11.8已部署888，盘点三个开关接通、托盘功能全局移除，019/原写入配置保持。49项前端、113项API通过/1跳过及Gateway合同通过，见[发布记录](DEPLOYMENT_2026-11-05_PRODUCT_ONLY_COUNT_SWITCHES.md)。

## 1. 标准流程及表头

原单可选 → 下一步扫码 → 确认盘点数量 → 完成做单 → 单据管理。

- 复用OutboundDocumentView和现有选单、明细编辑、单据管理组件，无独立采集页或手工核验步骤。
- 有原单：进入选单自动查询最近30天，可改日期/单号；卡片显示仓库名称/编码、日期、条数、制单人和未审核状态，一次选一张未审核单，不显示合并/明细模式或选单类型。读取完整表头、明细、原生行ID和指纹，先在标准IndexedDB保存草稿后返回；零扫码也可从单据管理恢复。保存失败留在选单页，不报成功。
- 有原单的日期和仓库带入并锁定；用户明确仓库需重置清空后才能更换。已有明细不能被另一原单覆盖。
- 是否盘货位只读：有原单读取bPosCheck；无原单选仓库后实时读取bWhPos。启用货位管理为是，未启用为否，未知/失败保持未确定，不按Position是否为空推断。状态随标准草稿保存；旧原单缺少状态须重选同一原单补齐，已盘记录保留。
- 无原单：可选择日期、仓库直接扫码制单，绑定当前API返回的真实账套/数据库，不伪造原单ID或空原单。
- 盘盈类别、盘亏类别均可改选。有原单先带入其值，空值及无原单默认使用档案中的盘盈入库107、盘亏出库207；保留用户后续改选，不以后台档案加载覆盖。盘盈只能选入库类别、盘亏只能选出库类别。
- 无原单已有扫码明细后仓库锁定，重置清空才可换仓库，避免跨仓串单。备注沿用标准字段。

## 2. 数量、读取和完成

1. 在线扫码实时查询TraceBack产品标签；余额为完整Code的SUM，位置为最大流水关联Goods。Code打印数量不用作余额或实盘默认值。
2. 在线新扫默认实时标签余额，自动添加开启且资料齐全时直接加入并保存，关闭则确认；缺盘点货位/离线未知数量/零实盘仍需确认；离线无余额保持空白，0也需确认，不覆盖已保存数量。隐藏标签数量展示，单位显示原单物料名称。同单重复完整Code警示拒绝，不累计/覆盖。负余额、旧表异常、缺失必要身份不得确认；不以标签原仓库/货位拦截。
3. 有原单另核对料号、批号和原生行；本次仓库取原单，无原单取制单表头；单位跟随原单物料，不比较旧标签单位文字与原单单位编码（2026-11-05用户要求）。目标仓库管理货位时必须确认本次盘点货位；原单盘货位时按用户选择的目标货位匹配原单，不要求标签原位置一致。目标不管理货位时清空货位；重复候选、自由项或辅计量不明确拒绝默认匹配。原单账面取iCVQuantity，原实盘iCVCQuantity保留null/0区别。
4. 确认数量实际提交标准草稿事务后才成功反馈；保存失败保留输入。后台同步使用原子版本保护，旧响应不得覆盖新数量。
5. 在线完成有原单调用/{id}/validate，前后核对原单指纹/账套/行及标签实时值；无原单调用/validate-direct，按最多100码一批读取快照，核对账套、仓库、异常和明确数量；查询标签前后实时复核货位管理标志，配置变化需重置后重试。两种方式最多1000个唯一Code。
6. 完成前数据变化、身份不符或核验不完整保留草稿并阻止完成。未扫标签不当盘0；U8命中行实盘按该原单已上传唯一Code最近实盘累计，未命中行保留。MATCHED不证明全仓应盘范围完整。

## 3. 保存与真实边界

原单确认/明细确认沿用普通草稿及009同步，保存原单快照/账套绑定。上传基线放通用操作事件，来源关联用通用业务单头，不引入采集任务、设备租约、专表或独立盘点库；原018辅助表已由019迁移删除。

完成做单先保存草稿；开启完成自动上传且在线、真实账套/能力匹配时立即上传，关闭/离线只保存。上传失败保留草稿及实盘。盘点开关为自动添加、完成自动上传、上传自动审核；三者均生效，托盘设置和业务路径全局移除，不新增后台重传。

## 4. 离线

- 已加载且会话有效的有/无原单页面可断网续扫，完整Code和明确数量存本机；未知身份显示待联网校验，不从Code猜身份/余额。新无原单须先联网取得账套绑定和所选仓库的真实货位管理状态。
- 离线完成只保存草稿；后续联网完成或未来上传必须实时复核。已同步与已上传ERP分开，不把网络图标当作授权。
- 制单/选单/明细/管理共用已安装APK的内部离线桥保护，不新增用户操作阶段。无网冷启动未实现，权限和会话到期规则不变。

## 5. 888上传保存与后续落账

有原单USERPCO窄字段Update复用原XML，不另建单；无原单Create独立读取U8账面。实盘取已上传唯一Code累计，不加账面；未命中行及账面保留。新规则实际保存由用户测试。

用户最新明确按已上传标签实盘累计：同原单、料批仓/按需货位，当前各Code实盘覆盖其旧贡献，其余历史贡献保留。同单重复扫码拒绝；跨次重新盘点替换原贡献，重试不重复累计。同一原单有未完成上传时先处理，通用UPLOAD_BASELINE事件冻结累计基线，未知结果重试载荷不变。

ERP确认后按每码实盘减提交前实时余额生成COUNT_ADJUSTMENT（含0），同步标签到本次确认仓库/货位，保留原位置作复核/审计；旧表同步失败保留任务/锁及ERP成功状态，仅恢复原事件。全部确认后新旧余额一致并解锁。用户49改50应追加+1；不得在后续审核再次落差异。自动审核开启时在差异同步后调用U8审核，失败沿原操作重试，不重复数量事件；独立手工审核/弃审仍关闭。
