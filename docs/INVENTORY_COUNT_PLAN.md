# 盘点单实施方案

复核与实施日期：2026-11-04。按用户要求收缩首期范围；[复核记录与后置项](INVENTORY_COUNT_REVIEW.md)单独保存，不把复杂配套全部放进首期。

## 1. 当前交付范围

本轮实现“读取原盘点单 → 本机在线/离线采集 → 联网只读核验”，尚未实现回填、审核生效和TraceBack差异落账。源码已构建并完成自动测试，尚未部署或进行888实单验证。

| 项目 | 源码状态 |
| --- | --- |
| 原单选择 | 新增盘点专用列表/明细读取，仅未审核单；最多100条搜索结果，明细完整性和数量检查 |
| 本机采集 | 独立盘点页，原单下载完成后写IndexedDB；每次扫码、保存数量、明确移除均用本地事务 |
| 重复扫码 | 同一任务完整Code重复则警示拒绝，不新增、不累计、不覆盖、不打开编辑；已保存记录重新加载后仍去重 |
| 实盘数量 | 默认空值，不读Code的打印数量；明确输入0才记0，最多12位整数和6位小数 |
| 联网核验 | 当前原单指纹、账户/数据库、Code、物料、批号、单位、位置及三表状态；每批最多100个Code |
| 旧上传拦截 | Business API建档/执行前拒绝盘点旧路径；Gateway盘点create能力关闭，避免ERP已新增才报同步不支持 |
| 安卓断网续扫 | 桥源码支持已打开采集页暂停远端健康遮罩/自动重载，并返回能力确认；旧APK会提示需要更新 |
| 无网冷启动 | 未实现，不以IndexedDB重新打开或启动动画代替APK无网启动验收 |

新页面只显示采集及核验状态，没有上传ERP按钮。`canSubmit=false`固定返回；原来的通用新建盘点代码不再作为开放入口。普通材料出库、调拨和货位调整流程不改变。

## 2. 原单与采集规则

1. 一份本机任务只关联一张原U8盘点单。原单ID、单号、行ID、原生版本、数量及完整行内容生成指纹；再次下载相同原单时复用本机任务。原单变化时保留原采集，不自动覆盖。
2. 原单账面数取CheckVouchs.iCVQuantity，原实盘取iCVCQuantity，二者分开。Code内数量不是当前余额，也不作为本次实盘默认值。
3. 本机数据按API来源、客户端环境、账号、U8账套/数据库及原单分开保存；不能只看客户端development名来区分888/008。
4. 每次扫码先把完整Code落盘，实盘未确认时为空。需要修改数量，从已有明细进入。保存失败不得播报保存成功；首次保存失败后可以重新扫描。
5. 未扫描不等于0。明确移除一条采集是用户操作，不自动从原单扣量；重新扫描已移除条码可以重新登记。
6. 原单书面行和标签按物料、批号、仓库、货位匹配，再核验单位；多个相同候选行、自由项或辅计量不明时标需核对，不默认选第一行。
7. 原单明细只显示“已匹配采集量”；它不是整行最终实盘。当前未证明应盘标签范围完整，任何匹配结果均不允许回填ERP。

## 3. 离线采集边界

下载的是原单及其完整明细，本轮没有全范围标签离线包、服务器任务锁、独立签名许可证或设备转交平台。离线只记录完整Code和人工确认实盘，不依据Code猜余额/位置；标签资料在联网核验时从旧三表取得。

已打开且会话仍有效的页面可以断网采集。复用现有登录到期规则，不增加8小时/24小时离线许可；退出/到期后本机记录保留，重新认证同账号后继续。联网核验不代表采集已同步服务端：本轮没有新增服务端盘点草稿表或上传队列。

新桥在接到可信H5的采集消息后，不因远端健康探测失败遮挡/刷新已加载页面。旧APK不识别该能力时显示升级提示。桥源码已经编译和脚本测试，但未签名发布或安装；当前安装版不能据此认定已支持。

应用页面重新联网装载后可以恢复IndexedDB记录；无网杀进程/重启后能否装载H5仍是单独未完成项。不能仅靠WebView缓存承诺完整无网冷启动。

## 4. 已实现的接口

以下为源码合同，未表示既有IIS已发布：

| 层 | 接口 | 行为 |
| --- | --- | --- |
| Gateway | GET /api/v1/inventory-counts?documentNo=&startDate=&endDate=&limit= | 未审核盘点单搜索；最多100条，hasMore提示缩小范围 |
| Gateway | GET /api/v1/inventory-counts/{id} | 只读返回账户、数据库、表头、稳定行ID、账面/原实盘、单位及自由项 |
| Business API | GET /api/v1/inventory-counts/capabilities | 盘点权限内查询；collectionEnabled=true、canSubmit=false、offlineColdStart=false及来源范围 |
| Business API | GET /api/v1/inventory-counts | 权限校验后使用固定查询参数代理，不接受客户端SQL或任意网关路径 |
| Business API | GET /api/v1/inventory-counts/{id} | 校验Gateway账套与配置一致、完整明细，并产生原单指纹 |
| Business API | POST /api/v1/inventory-counts/{id}/validate | observations包含完整Code及字符串quantity；上限1000张、拒绝重复；只读快照，不写镜像/U8/旧三表 |

核验前后各读取一次原单；原单指纹变化整批拒绝、保留本机数据。部分标签不存在、身份/单位不符、旧表异常或实盘未填时逐条提示。核验响应在本机采集修订已变化或已启动更新核验时作废，不能覆盖新记录。

即使全部MATCHED，也只表示当时身份匹配；本轮不声称验证盘点全过程没有外部移动，也不声称已盘完整个库存范围。

## 5. 下一阶段：原单回填及差异生效

继续开发前先只读核查888真实原单、USERPCO Update参数/原XML和审核/记账行为，再固化写合同。使用窄字段原单回填，不重新生成另一张盘点单，不开放其他单据的通用修改/删除。

回填前必须证明原单行范围完整，重新查询旧三表最新流水、余额、位置及范围新增/移出。未盘标签不自动当零，U8账面和标签余额存在未解释差异时不自动摊分。原单的所有行未完成时不自动审核整单。

建议标签差异在审核回查确认后生效；888实际审核/记账行为须验证后固定。按每码“实盘－有效冻结余额”产生盘盈/盘亏事件，例如原单账面100、标签60/40、实盘55/42，则回填97、原码分别－5/+2。零差异不追加旧表数量。

本地差异和稳定同步任务原子保存；旧表失败保留ERP结果和占用，只恢复原事件。已生效盘点不直接开放弃审/撤销，需另行核对后续库存动作。候选迁移018只在需要服务端任务/占用/同步结构时新增，本轮没有创建或执行迁移。

## 6. 验证与放行

本轮自动测试覆盖IndexedDB真实事务模拟的并发重复扫码、失败回滚、明确盘零、账号/来源隔离、关闭重开后去重、旧修订/核验响应保护、精确小数合计；Business API测试覆盖原单完整性、源指纹、异常标签、单位/位置、批量100拆分和写入前拦截；Gateway纯合同测试不连接SQL/COM。

APK桥使用实际生成脚本测试可信窗口/来源、断网遮罩及探测返回竞态，并单独Java编译。没有查看页面截图，没有调用打印或更改运行环境。

自动测试通过不代替真实888源单查询、PDA物理扫码/警示声及断网实测。新H5需对应新Business API/Gateway；APK桥需重新构建、安装后单独验收。生产008不在本轮部署或写入范围内。
