# 盘点单实施方案

快速查看已支持能力、限制、操作与验收状态，进入[盘点功能档案](features/盘点单.md)；本方案保留详细实施及后续ERP边界。

现行方案：2026-11-04，H5 dev.87 / Business API0.12.3 / Gateway0.11.2。用户明确盘点沿用现有制单方式，同时支持有原单和无原单；本版替代此前原单必选、类别只读和独立采集流程。界面规范见[UI_DESIGN.md](../UI_DESIGN.md)，页面及验收见[页面记录](PAGE_DESIGN_RECORD.md)。

## 1. 标准流程及表头

原单可选 → 下一步扫码 → 确认盘点数量 → 完成做单 → 单据管理。

- 复用OutboundDocumentView和现有选单、明细编辑、单据管理组件，无独立采集页或手工核验步骤。
- 有原单：按单号/日期查询一张未审核单，不显示合并/明细模式或选单类型。读取完整表头、明细、原生行ID和指纹，先在标准IndexedDB保存草稿后返回；零扫码也可从单据管理恢复。保存失败留在选单页，不报成功。
- 有原单的日期和仓库带入并锁定；用户明确仓库需重置清空后才能更换。已有明细不能被另一原单覆盖。
- 是否盘货位只读：有原单读取bPosCheck；无原单选仓库后实时读取bWhPos。启用货位管理为是，未启用为否，未知/失败保持未确定，不按Position是否为空推断。状态随标准草稿保存；旧原单缺少状态须重选同一原单补齐，已盘记录保留。
- 无原单：可选择日期、仓库直接扫码制单，绑定当前API返回的真实账套/数据库，不伪造原单ID或空原单。
- 盘盈类别、盘亏类别均可改选。有原单先带入其值，空值及无原单默认使用档案中的盘盈入库107、盘亏出库207；保留用户后续改选，不以后台档案加载覆盖。盘盈只能选入库类别、盘亏只能选出库类别。
- 无原单已有扫码明细后仓库锁定，重置清空才可换仓库，避免跨仓串单。备注沿用标准字段。

## 2. 数量、读取和完成

1. 在线扫码实时查询TraceBack产品标签；余额为完整Code的SUM，位置为最大流水关联Goods。Code打印数量不用作余额或实盘默认值。
2. 数量首次为空，0必须明确确认；同单重复完整Code警示拒绝，不累计/覆盖。负余额、旧表异常、缺失必要身份、仓库不符不得确认。
3. 有原单另核对料号、批号、仓库、单位和原生行；盘货位时必须有货位并按货位匹配，不盘货位时按仓库维度匹配但保留最新标签位置；重复候选、自由项或辅计量不明确拒绝默认匹配。原单账面取iCVQuantity，原实盘iCVCQuantity保留null/0区别。
4. 确认数量实际提交标准草稿事务后才成功反馈；保存失败保留输入。后台同步使用原子版本保护，旧响应不得覆盖新数量。
5. 在线完成有原单调用/{id}/validate，前后核对原单指纹/账套/行及标签实时值；无原单调用/validate-direct，按最多100码一批读取快照，核对账套、仓库、异常和明确数量；查询标签前后实时复核货位管理标志，配置变化需重置后重试。两种方式最多1000个唯一Code。
6. 完成前数据变化、身份不符或校验不完整保留草稿并阻止完成。没有扫描不等于盘0，扫码和不代表原单整行最终实盘；MATCHED不证明应盘范围完整。

## 3. 保存与真实边界

原单确认和明细确认均使用普通草稿机制、既有009服务端草稿同步与单据管理。原单完整快照、用户表头选项及inventoryCountContext分开保留。旧独立记录幂等导入并保留原库，删除不复活；不新增任务、设备租约、SQL表或迁移。

“完成做单”仅保存标准待上传草稿。U8原单回填、无原单新增、完整应盘范围及TraceBack差异生效尚未完成，上传及自动上传均保持禁用，不能把草稿保存宣称为U8已写入。

## 4. 离线

- 已加载且会话有效的有/无原单页面可断网续扫，完整Code和明确数量存本机；未知身份显示待联网校验，不从Code猜身份/余额。新无原单须先联网取得账套绑定和所选仓库的真实货位管理状态。
- 离线完成只保存草稿；后续联网完成或未来上传必须实时复核。已同步与已上传ERP分开，不把网络图标当作授权。
- 制单/选单/明细/管理共用已安装APK的内部离线桥保护，不新增用户操作阶段。无网冷启动未实现，权限和会话到期规则不变。

## 5. 后续ERP落账

先在888验证真实业务：有原单使用USERPCO窄字段Update及原XML，不另建一张；无原单单独验证Create及可写表头/明细。用户改选类别必须在真正写入前重新验证，不因本机可选就自动开放U8修改。

两种方式均需明确完整应盘范围，写入前实时复核旧三表最新流水、余额、位置及新增/移出。未扫不当零，标签与U8账面差异不自动摊分，未完成全部范围不自动审核。

差异生效时机仍需888实证；拟按每码实盘减有效基准余额生成稳定盘盈/盘亏事件，零差异不追加数量。ERP结果与失败恢复沿用既有原则，重试不得重复事件；已生效盘点暂不直接开放弃审。只有确需服务端结构才新增018迁移，本轮没有创建。
