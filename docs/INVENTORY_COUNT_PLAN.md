# 盘点单实施方案

现行方案：2026-11-04、H5 dev.85。用户要求盘点按现行制单标准执行，不要独立“采集”功能；此前dev.82/83的独立页面和手工联网核验设计被本方案替代。界面规范见[UI_DESIGN.md](../UI_DESIGN.md)，页面及验收记录见[页面记录](PAGE_DESIGN_RECORD.md)。

## 1. 标准操作流程

选源单 → 下一步扫码 → 确认盘点数量 → 完成做单 → 单据管理。

- 盘点和材料出库直接使用同一个OutboundDocumentView、确认弹层、SourceDocumentSelectView、源单明细和单据管理组件；删除独立InventoryCountView。
- 盘点原单查询只有单号/日期条件，列表显示单号、日期、仓库和明细数，一次选一张未审核盘点单。没有“合并/明细”、选单类型切换或产品筛选。
- 日期、仓库及盘盈/盘亏类别编码和名称来自原单并只读；备注沿用标准字段，盘点数量通过标准明细确认。0必须明确确认，不默认填Code的打印数量。
- 确认明细后用标准IndexedDB草稿事务保存，成功才反馈；完成做单保存同一草稿并进入标准单据管理，与其他制单的含义一致。
- 自动后台校验，界面没有单独“联网核验”按钮、采集记录、任务列表或手工同步阶段。管理页复用既有草稿同步和继续编辑。

## 2. 当前实现及真实边界

H5 dev.85代码/构建及24项自动测试通过，发布状态见页面记录；Business API为0.12.1、Gateway0.11.1，APK仍为0.5.5/111。本轮补充两层API只读类别合同，没有新迁移或U8写接口。

“完成做单”是保存待上传草稿，不表示ERP已有结果。盘点原单回填、完整应盘范围及TraceBack差异生效尚未实现，管理页明确显示禁用的“上传暂未开放”；前后端旧新增路径仍受阻，不用改名绕过门禁。

原单读取和后台校验已有008/888发布/只读验证；新页面的实机外观、物理重复扫码、声音、键盘和断网仍分别验收，不把自动测试当作现场完成。

## 3. 业务数据与自动校验

1. 一张草稿绑定一张原U8盘点单及完整行ID/源指纹。不能同时选择多个盘点单或只选其部分明细；相同原单行的未上传草稿冲突沿用标准选单检查。
2. 在线扫码沿用库存对象实时查询，标签资料来自TraceBack三表。核对物料、批号、仓库、货位、单位；重复完整Code警示拒绝，不累计、不覆盖、不打开旧记录。
3. 标签余额用旧三表SUM；最新位置按最大流水ID的Goods。Code打印数量不作为余额或本次盘点量。
4. 原单账面取CheckVouchs.iCVQuantity，原实盘为iCVCQuantity，保留null和0区别。标签可明确盘为0；未扫描不等于0，不把当前扫码和当成整行最终实盘。
5. 在线完成做单时自动调用原单/标签校验：服务端前后核对原单指纹、账套、数据库和标签状态，再按原单行匹配；发生异常保留草稿并阻止完成。位置/单位不符、多个候选行、自由项或辅计量不明不能默认匹配第一行。
6. 新数量、后台请求返回和保存处理中禁止误扫码/覆盖输入；旧结果不能覆盖更改中的表单。所有真正U8写入前的实时范围/版本复核仍属下一阶段，不能用本次只读校验代替。

## 4. 离线与历史数据

- 已打开且会话仍有效的盘点单据可断网扫码，离线只保存完整Code及明确盘点数量，不猜余额/物料身份；未知身份简短显示“待联网校验”。
- 离线确认/完成保存在普通草稿库，联网后使用既有草稿同步。重新完成或后续真正上传必须实时复核，不能以离线草稿替代权限和库存授权。
- 制单、选单、源单明细和单据管理使用相同内部离线桥保护，防止已加载页面被远端健康探测遮挡；沿用已安装APK的offline-collection消息名称，不把协议名变成用户操作概念。
- 旧独立IndexedDB数据读取后导入标准草稿，保留来源及完整Code、null/0；重复进入不重复导入，已删除记录不复活，不清除原始数据。新盘点只使用普通草稿机制。
- 原已保存用户仍按当前会话到期和权限规则重新认证；不加独立签名许可、设备转交或8小时/24小时配置。无网冷启动未实现；旧APK需升级后才有对应壳保护。

## 5. 后续：原单回填和差异生效

开发真实上传前，在888核查USERPCO Update窄字段、原XML以及审核/记账行为；更新原盘点单，不重新生成另一张单，不开放其他业务通用修改/删除。

上传必须证明完整应盘范围，实时复核旧三表的最新流水、余额、位置和新增/移出。未扫不自动当零，标签与U8账面未解释差异不自动摊分；未完成原单所有行不得自动审核整单。

差异生效时机仍需888实证；拟按每码“实盘－有效基准余额”生成盘盈/盘亏事件，零差异不追加数量。ERP结果、稳定同步事件和失败恢复沿用现有业务原则，不能重试时重新生成事件。已生效盘点暂不直接开放弃审/撤销。

候选迁移018仅在真实回填/差异业务确实需要服务端字段时新增；本轮没有新增盘点任务、设备租约、服务端表或迁移。
