# 功能开发基准

2026-11-05用户确认，适用于标签管理系统所有功能。

1. **先能落地使用。** 优先做当前业务最基础的一条完整流程：输入/扫码、确认、保存、上传、返回结果和必要的失败重试。不要等理想的全套功能完成才允许正常使用。
2. **保持简单。** 不主动增加复杂流程、任务平台、审批层级或大量开关。非必要需求记入对应功能档案的后续事项，说明即可，不先实现。
3. **沿用现有通用结构。** 优先复用页面、业务单头/明细、库存流水、同步任务及操作事件。能放进现有记录的基线、日志和附加数据，不为每个功能单独建表。确需新增时，先说明用途、不能复用的原因及影响。
4. **已支持的流程直接可用。** 不因为“以后还要做审核”“尚有进阶能力未完成”等理由额外禁止保存、完成或上传；现有开关按实际含义生效。不显示能打开却不执行的选项。
5. **保留必要校验。** 登录与权限、当前账套和明确写入范围、数量与位置有效性、防重复写入及失败数据保留继续执行；不能为简单而错账、串账或丢记录。账套/生产写入配置按用户当前明确设置，不由本基准自动扩大。
6. **少步骤、少说明。** 沿用标准操作页面，用简短业务文案；技术细节放文档。额外确认只用于确实必要的业务动作。
7. **按改动大小验证。** 只查相关文件、做必要测试和发布核对，通过后继续交付。功能、限制、已部署与实测状态在现有档案中维护，不另建重复平台。
