# 盘点方案复核与后置记录

资料复核：2026-11-05。当前基线为dev.87 / API0.12.3 / Gateway0.11.2，部署及测试证据仍是[11月4日记录](DEPLOYMENT_2026-11-04_COUNT_COLLECTION.md)；今日只核对本地代码/文档，没有重新部署、实测或写业务数据。

## 1. 现行结论

- 盘点直接使用共用制单、选单、明细和单据管理组件，原单可选；不再使用独立采集页、任务列表或手工联网核验步骤。
- 有原单先完整保存本机草稿，日期/仓库锁定，重置清空后才可换仓库；无原单可选择仓库和日期。盈亏类别可选，默认107/207，不能继续沿用dev.85的类别只读约束。
- 是否盘货位为只读状态：有原单读bPosCheck，无原单实时读bWhPos。未知不当否，盘货位时标签须有货位；不盘货位仍保留标签最新位置。
- 新记录写标准IndexedDB草稿并复用009同步；首批独立库仅导入历史数据。原单确认、数量确认保存成功后才能反馈，旧同步/切仓响应不得覆盖新输入。
- 重复完整Code警示拒绝；数量首次为空，0明确确认。在线完成前自动复核原单/仓库与旧三表，离线仅在已加载有效会话页面续扫。
- 专用盘点核验不写盘点操作/差异流水；标准扫码查询可以刷新本地标签镜像。保存本机、同步草稿、上传ERP分别处理。
- ERP新增/回填、完整应盘范围及差异生效未完成，上传/自动上传仍禁用；独立离线许可、任务租约和无网冷启动均后置。

## 复核发现与处理

| 问题 | 处理 |
| --- | --- |
| 原来只给盘点加选单容易沿用“新增一张单” | 独立盘点采集页，原单ID/行ID保留；回填没有验证前不开放新增 |
| 单张标签余额不能代替U8整行账面，多张标签也不能各建一张盘点单 | 原单账面与标签当前余额分开，采集量只作采集汇总，不标为可回填 |
| 原方案“重复扫打开原记录”与用户要求冲突 | 重复扫码警示拒绝；修改从明细进入，事务去重覆盖并发和重新加载 |
| 离线采集和离线改账混在一起 | 先本机采集及联网核验，不离线写U8/旧三表，不把采集保存说成服务端同步 |
| 已有IndexedDB不等于无网冷启动 | 已打开页面续扫与离线重启分开；后者未实现，桥升级也需实际安装验收 |
| 另建签名许可、8小时时长和设备转交过重，且与当前会话到期规则不一致 | 首期不实施，复用现有有效会话；没有擅自改离线时长配置 |
| 原方案下载范围/占用/迁移都先做，会把只读阶段耦合到长锁和新表 | 首批下载原单、本地存储，不新增服务端迁移或占用；上传前范围完整性属于下一阶段的硬条件 |
| 旧盘点新增可能在ERP已写入后才因不支持TraceBack报错 | Business API建档/执行前拦截，Gateway盘点create=false；不依赖页面隐藏按钮 |
| 原单/核验期间数据会变、网络响应会乱序 | 服务器前后核对原单指纹，本机核验令牌及修订保护，旧结果不覆盖新输入 |
| 金额式浮点累计或BigInt可能带来精度/旧PDA兼容问题 | 数量用最多6位小数字符串，精确字符串合计，不依赖BigInt |
| 安卓远端探测返回竞态会挡住刚打开的离线任务 | 采集消息按窗口/来源校验，探测完成时重查采集状态；旧壳未确认能力则提示更新 |
