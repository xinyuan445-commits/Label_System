## 2. 业务差异

| 业务 | 保留的差异 |
| --- | --- |
| 材料出库 | 原单/无原单、蓝红字、领料/退料及超领相关字段和确认 |
| 调拨 | 明细调出/调入位置，表头调出/调入部门，关联单审核 |
| 货位调整 | 位置调整及部分移动，不伪造调拨单字段 |
| 采购/销售/委外 | 各自来源类型、数量和批号要求；页面相同不表示所有业务已验收 |
| 盘点 | 原单必选，日期/仓库只读；实盘须明确确认；后台校验；共用标准草稿，ERP上传尚未实现并禁用 |

## 3. 盘点现行设计（dev.85）

- 制单/编辑/底栏全部直接使用材料出库的同一个组件；日期、仓库和盘盈/盘亏类别带自原单，只读，盘点数量通过标准确认弹层输入，0需明确确认。
- 选单使用标准/source路由和查询列表；按单号/日期查询单张未审核盘点单，显示仓库及原单条数，不提供合并/明细模式或选单类型。读取完整原单和行ID后返回。
- 在线扫码实时查标签；离线只保存完整Code及明确数量，显示必要的“待联网校验”，不从Code猜余额。编辑确认事务落标准IndexedDB后才反馈成功。
- “完成做单”在线时自动实时校验原单与三表，失败保留草稿；离线可保存待上传草稿，后续联网操作必须重新校验。不能把保存草稿表述为U8已写入。
- 旧独立记录转为普通草稿、保留原始数据；管理、继续编辑和同步复用现有功能，删除的记录不自动复活。ERP回填和差异落账尚未完成，管理页明确禁用盘点上传。
- 不新建盘点任务、设备租约、数据库表或新的操作阶段；APK原协议仅作为已加载单据页的内部离线保护，制单/选单/明细/管理页面之间都保持此保护。
