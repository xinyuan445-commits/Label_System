## 1. 功能说明

在新系统与旧追溯系统并行期间保持标签余额、位置和来源一致，是材料出库、调拨、货位调整及盘点查询的重要共同边界。

## 2. 已支持功能

- 单张及最多100码批量产品标签快照，来源、余额、最新位置及异常分类。
- 扫码建立/刷新本地镜像；材料出库、调拨、货位调整建档前和写U8前实时复核。
- 三类业务来源事件、幂等任务及失败恢复；开发打印首打初始登记另有专用事件。

## 3. 操作流程

扫码实时读取 → 校验身份/余额/位置 → 建立或刷新镜像 → 业务建档及写U8前再次复核 → 确认ERP结果 → 依原业务事件同步旧表 → 完成后释放相应限制。盘点目前只查询/核验，差异写入尚未接通。

## 4. 规则与限制

- 已有标签权威来源为TraceBackOrder、TraceBackGoods、TraceBackOnlyCode；余额按完整Code求SUM，当前属性/位置按最大流水ID关联Goods。
- Code中的数量只作打印快照。负余额、Goods缺失/重复、无效JSON或身份冲突进入待核对，不能盲目复制历史异常。
- 本地product_label/inventory_flow承载镜像、锁、待打印及审计，不作为迁移期独立权威余额。
- 蓝字材料出库原Code负流水，原标签红字正流水；全量移动零流水并更新位置，部分移动来源负流水且保留来源位置，目标首打后新Code正登记。
- 无标签退料及部分移动目标在制单时不写空Code/临时Code；首打登记、补打和来源事件不能重复累计数量。
- 同步失败沿原事件恢复；ERP已成功不能靠再做一张单解决。审核/弃审不直接新增或冲销旧表数量流水。
- 三类来源事件的实现不推广到全部九类单据；盘点ERP差异写入未完成。托盘只使用本地表。
- 不能未经验证修改生产索引；当前索引候选尚未实施，不把源码方案当作数据库已优化。
