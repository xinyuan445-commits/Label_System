# 发货单

## 2026-11-06当前状态

dev.96 / API0.13.1 / Gateway0.12.1 / Dev020已部署888。发货固定蓝字，提供销售订单/无原单入口；退货使用独立[退货单](退货单.md)，旧红字记录不转蓝。

- 销售订单来源行使用真实iSOsID，不能用另一个AutoID；计划=iQuantity、已发=iFHQuantity、剩余=两者差，兼容orderQuantity仍表示可发量。提交和写U8前重新核对，不允许超发。
- 选原单带回客户、部门、销售类型、币种、汇率；客户及原单关键财务信息只读，不同客户/类型/币种不能合并。单价、税价、税率保存在通用归档salesSourceLines，价格/客户变更需重选，扫码记录保留。
- 在线默认当前标签余额，并受订单剩余约束；同料多行按剩余分配，原单详情显示订单/已发/可发、本单已拣/待扫。不能照搬材料超领规则。
- 产品标签来自旧三表，提交前刷新镜像、写U8前复核最新流水/余额/身份/位置。异常、余额不足、仓库不符、重复码、权限和写入范围校验保留。
- 发货不扣标签、不产生TraceBack数量任务，复用通用业务/ERP关联和草稿。首次镜像初始化余额来自旧表，不是发货增加库存。实际库存业务在销售出库处理。
- 原请求重放先找既有业务，不因其已消耗来源量而重复新增；通用上传仍最多500行，包括来源分配后的行。

## 1. 功能说明

处理发货单。现有配置来源为销售订单，表头包括客户、仓库、部门、日期及发货明细。

## 2. 已支持功能

| 能力 | 已确认范围 | 验收边界 |
| --- | --- | --- |
| 来源查询/选择 | 已有来源映射和共用选单页面；六类来源有888只读验证记录 | 读取成功不等于新增或回写成功 |
| 表头、扫码和明细确认 | 共用制单框架已有；页面配置提供蓝/红字选项 | 具体业务规则须逐类型核验 |
| 草稿及上传/审核接入 | 共用草稿、通用新增/审核接口基础已有 | 不据按钮或capabilities判断端到端可用 |

## 3. 操作流程

选择本业务来源 → 填写适用表头 → 扫码/确认明细 → 保存草稿。真实上传、红字和审核的测试范围先按当前账套与已验收证据确认。

## 4. 规则与限制

- 与材料出库、调拨、货位调整分开记录；这三类的旧三表同步验收不能推广到本功能。
- 数量、批号、来源行分配、业务类别和权限按本类型服务端规则校验，不能因共用组件就照搬其他业务结论。
- 不承诺离线扫码或离线写ERP；前端功能可见不等于有服务端写入权限。
- 本页没有足够证据将全部新增、红字及审核场景标记为现场通过。

## 5. 未完成与后续

按888真实样例补齐新增、来源关联、蓝/红字、审核/弃审、失败恢复、标签数量与旧追溯边界；再记录008现场验收。发现不适用的操作应明确禁用或记录原因，不能虚填通过。
