## 基础流程

可选择原发货单、销售订单，也可无原单 → 选择本次仓库、客户等适用表头 → 扫产品标签、填写正数退货量 → 保存草稿 → 按开关上传/自动审核。界面不显示红蓝字，服务端固定生成U8退货方向、负数量。

退货只登记销售业务，不直接增加标签余额；实际ERP库存影响取决于U8配置及后续销售退库处理，当前尚未完成真实审核/库存影响验收。不能把发货/退货和销售出库/退库重复计算标签数量。

## 规则与限制

- 原发货单：已审核蓝字，按发货量减已退量；存在销售订单关联时还受订单净已发量约束。多张原发货单共享一个订单行时合并控制可退总量。
- 销售订单：iFHQuantity已扣退货，直接作为可退量；累计已发=iFHQuantity+fretquantity，已退=fretquantity，不能再减一次。已完成订单退货不套用蓝字剩余/关闭筛选。
- 原单带入客户、部门、销售类型、币种及汇率；客户和关键财务信息只读。同客户同类型同币种才可合并选择。源单价格快照保存在通用归档的salesSourceLines，提交/写U8前复核，客户端改价不能放行。
- 扫码允许正常USED/零余额产品标签，退货量需手填正数，不以当前余额代替可退量。无原单不等于无标签；无标签退货/生成新标签不在本轮范围。
- 目标仓库取本次表头，必要位置用通用明细编辑；本单不改变标签当前位置。负余额、Goods异常、重复码、身份、权限及写入范围校验保留；通用上传最多500行，包括来源分配后的明细。
- 扫码、提交及写U8前读取旧表最新资料；不生成TraceBack数量任务。首次镜像可能新增初始化流水，其余额来自旧表，不是本次退货增加库存。
- 原请求重放先找既有业务，不重复新增；审核和失败记录复用原业务组。独立退货审核入口未新增，上传自动审核不等于独立手工审核/弃审已验收。

## 数据与状态

复用business_operation（SALES_RETURN）、business_operation_line、business_operation_event、通用草稿和归档。U8仍为DispatchList/DispatchLists、bReturnFlag=1；原发货关联iCorID/cCorCode，订单关联真实iSOsID。

020只注册system_function和三个默认关闭的通用设置，不新增业务表或复制发货权限；普通用户需单独配置退货权限。原用户设置未代改。

U8财务供应链制造许可已饱和，正在等待用户释放一个许可；本轮尚未创建发退货测试单。待验：两种原单/无原单实际保存、数量/来源/金额回写、审核、重放与PDA。无原单沿用既有输入及U8默认计价，未补报价或价表功能，金额仍待实测。仅888发布，生产008未改，见[发布记录](../DEPLOYMENT_2026-11-06_SALES_DOCUMENTS.md)。
