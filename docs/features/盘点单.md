## 1. 功能说明

按现有单据格式进行有原单或无原单盘点，保存明确盘点量并联网复核。不提供独立采集任务页。

## 2. 已支持功能

| 能力 | 当前行为 |
| --- | --- |
| 有原单 | 单张未审核原单；进入自动查最近30天，可改日期/单号，无合并模式；卡片显示单号、仓库名称/编码、日期、条数、制单人及实际未审核状态；完整表头、明细、行ID和指纹确认后立即存本机草稿 |
| 无原单 | 选择日期/仓库直接扫码制单，保存真实账套绑定，不伪造原单 |
| 仓库 | 有原单锁定，需重置清空后更换；无原单已扫码后同样锁定，避免跨仓串单 |
| 盈亏类别 | 可改选；有原单先带入原值，空值或无原单默认盘盈入库107、盘亏出库207 |
| 是否盘货位 | 只读；有原单取原单状态，无原单选仓库后取真实货位管理标志；不按货位列表是否为空猜测 |
| 数量与去重 | 在线默认当前余额，可修改后确认；离线无余额留空，0需确认；重复完整Code警示拒绝，不累加、不覆盖 |
| 保存与离线 | 标准本机草稿、既有同步/继续编辑；已加载有效会话页面可断网续扫 |
| 在线完成 | 有原单复核源指纹/标签，无原单核对仓库/标签；先保存草稿，按开关及实时能力自动上传；失败保留草稿 |

## 3. 操作流程

可选原单 → 表头 → 扫码确认实盘 → 完成做单先保存草稿 → 开启完成自动上传且在线/888能力匹配时自动上传 → 单据管理。关闭开关只保存，离线保存后需联网手动上传；审核/弃审继续关闭。

盘点开关仅展示“完成自动上传”；隐藏未支持的自动审核、自动加明细及托盘项，保存不覆盖隐藏开关和全局托盘设置。详见[本次发布](../DEPLOYMENT_2026-11-05_COUNT_JSON_SWITCHES.md)及[JSON合同](../TRACEBACK_COUNT_JSON_CONTRACT.md)。

## 4. 规则与限制

- 已有标签实时资料来自旧三表；打印数量不作余额或实盘默认值，未扫不当盘0。合法零余额/已用完产品标签可参与盘点，实盘0仍需明确确认，负余额或异常不能据此放行。
- 共用表单使用JavaScript数值，极大数量/精度边界尚未整链验收，不以旧独立模型的字符串合计测试替代。
- 单单最多1000个唯一完整Code；原单最多5000行，查询超出列表范围需缩小条件。
- 盘点不以标签原仓库/货位限制扫码。有原单以原单仓库为准，无原单以制单表头为准；目标仓库启用货位管理时在数量确认中选择有效“盘点货位”，原单盘货位时限匹配料号/批号的原单货位。跨仓不猜货位，未启用货位管理时清空目标货位。上传ERP确认后，新旧标签余额按实盘同步、当前位置按本次目标更新；扫码和草稿不改变标签。原位置留作实时复核和审计，未扫标签不变。
- 原单与仓库货位管理标志分开读取；未知/失败不能默认否。旧原单草稿缺状态时重选同一原单，已盘数量保留。
- 单位跟随原单物料，不比较旧标签的单位文字与原单单位编码；无原单仍沿用标签物料资料。负余额、旧表异常、原单重复候选或自由项/辅计量不明确不能默认通过。
- 无原单完成前前后复核仓库配置，变化需重置后重试；快速切仓的旧响应不能覆盖新仓库状态。
- 新无原单先联网取得账套和仓库状态；只支持已加载页面续扫，无网冷启动未实现。离线记录后续必须实时复核。
- 原单完整快照不是全仓标签离线包；U8命中行实盘取同一原单、料批仓/按需货位已上传标签实盘合计，不加账面。未命中行、未扫标签余额保留。
- 同码跨次重新盘点替换原贡献，重试不重复累计；同单重复扫码拒绝。同一原单有未完成上传时先恢复/处理原业务。
- 上传确认后按实盘减实时余额追加COUNT_ADJUSTMENT；零差异追加0，本地镜像同步后才完成并解锁。托盘暂缓；审核/弃审关闭，不得后续再次落同一差异。
