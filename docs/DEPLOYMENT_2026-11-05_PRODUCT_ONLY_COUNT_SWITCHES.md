## 本次范围

按用户确认，全系统业务改为独立产品标签，不再提供托盘业务。覆盖九类共用制单、开关设置、标签查询、条码规则、上传/执行与共用打印回执；产品标签首打、补打及部分移动待打印保持。Android桥只转发条码，没有托盘专用逻辑，本次不换APK。本次未修改独立打印项目；正式首打/补打API仍只使用产品标签。

- 删除扫托包含托盘、混料/混批/混仓/混货位、空托复用、托内标签单独使用等设置和前端缓存值；API不再返回或允许重新启用这些设置。
- 删除扫托展开、整托数量/位置限制、托盘联动删除和查询展示；标签原装托关系不再参与正常产品查询、镜像或制单。
- 禁止新建托盘条码规则，不再返回/激活原托盘规则，过滤旧客户端规则缓存；产品/通用/外部规则保留。
- 旧托盘草稿/已建业务保留。含托盘或来源托盘的旧记录不能继续执行、上传或恢复追溯任务，不自动改成产品单。旧草稿删除相应明细后重新扫码；已建操作需先核对原状态。
- 新业务明细的托盘关联为空，产品打印新流水不再复制旧托盘归属。旧托盘表、关联表、外键、字段和历史流水保留，仅历史读取及取消旧业务释放原锁需要的代码保留。无迁移，不改已执行SQL、不删除历史数据。

| 开关 | 当前行为 |
| --- | --- |
| 扫码后自动添加到明细 | 开启且实时数量/必要货位齐全时，按当前余额直接落标准本机草稿；关闭则确认数量。跨仓缺目标货位、离线数量未知、零实盘仍进入确认；重复完整Code警示拒绝 |
| 完成自动上传 | 保持既有保存草稿后上传策略；关闭/离线只保存，上传失败保留输入 |
| 上传自动审核 | 开启后，ERP保存并同步原COUNT_ADJUSTMENT事件成功后调用U8审核；关闭只保存未审核单。失败使用既有待审核/待核对和原业务组恢复，不重新新增ERP或调整标签 |

审核不再次生成TraceBack差异。Gateway仅在888测试账套允许盘点verify；Add/Edit继续要求盘点保存合同，Unverify/Delete仍拒绝。审核结果未知后重试，由Business API按NEEDS_RECONCILIATION/FAILED状态生成countApprovalRecovery标志；若真实状态已审核，直接确认当前状态，不因旧版本再次调用原生审核。普通上传及非恢复审核仍严格比较expectedVersion，不能忽略他人修改。Business API的独立手工审核/弃审入口保持原边界；失败审核从单据管理沿原操作重试。共用组validate/execute按真实单据功能校验权限，修复原先固定要求材料出库权限的问题。
