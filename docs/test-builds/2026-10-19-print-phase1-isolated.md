## 联调发现与修复

`Printing/PrintArtifacts.cs` 原先以 `JsonContent` 向 Python HTTP 服务发送分块请求，而渲染服务仅按 Content-Length 读取请求，因此真实 HTTP 联通时返回422。现改为 UTF-8 `StringContent`，提供确定请求长度；随后所有首打、补打、历史补打均通过实际回环 HTTP 渲染。

其余排查失败来自验收宿主的跨 .NET SQL 连接关键字、测试夹具的规则/画布格式、rowversion编码及故障注入方式，未作为产品缺陷或通过证据。早期触发器注入会触发SQL Server对OUTPUT的限制，正式验收改用仅影子库的临时CHECK约束，撤销后再恢复登记。

回归：Business API纯测试36通过（排除独立建库的MaterialCacheRepositoryTests）、Python9通过、Go全部通过（普通运行跳过显式验收桥）。API及两个验收宿主构建通过。未改前端，本轮未重复现场页面验收。

本轮选择临时库，是为了隔离故障注入和合成数据，避免污染已有开发库。用户询问后已明确：保存验收记录再删除；后续常规联调优先复用现有开发库，破坏性故障用例单独隔离。
