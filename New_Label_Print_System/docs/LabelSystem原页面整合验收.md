## 来源、数量与防重

| 阶段 | 当前行为 | 不重复落账依据 |
| --- | --- | --- |
| 原页面查询/预览 | 查 U8，按包装显示预计张数；使用预览值 | 不申请正式流水，不建打印任务，不写旧三表 |
| 来源预约 | Flask 重新查询实际888单据/库存、单位档案、旧标签进度；签发绑定当前用户和短有效期的来源摘要 | 浏览器不能自行提交可信额度；未开放任意代理签名入口 |
| 已有业务待打印目标拆包 | 原目标扣除被转移数量，生成包装子目标和未选数量的余量目标 | 同一 SQL 事务中 `LABEL_PACK(-Q)` 与子目标 `LABEL_SOURCE(+Q)` 合计0；原业务单据不重做 |
| 单据/库存首次建标 | 建立来源操作及无Code的待打印目标 | 属于现存单据/库存的标签初始表示，不调用 U8 制单或增减 `CurrentStock`；来源请求只建一次并占用额度 |
| 准备首次任务 | 校验目标/来源/行版本、冻结模板和数量、按唯一当前规则分配Code | 编码唯一登记；已分配目标不能换请求再首打；准备失败/结果未知保留原请求和目标 |
| 模拟助手接受发送 | 保存真实签名回执，本地 `PRINT(0)` 与旧三表初始正流水登记 | 每输出、标签首次事件、同步事件及旧三表确定性键防重；无法确认实际出纸，不作为成功标准 |
| 补打 | 冻结原首次内容、原Code及原模板版本；历史标签先核验旧首打依据 | 每份 `REPRINT(0)`；不新建Code、不追加旧初始正流水，不用当前余额改写原纸面数量 |
| 丢回执/三表失败 | 查询原job/attempt的持久回执，或仅重试原同步任务 | 不重发数据，不新建来源、首打或旧初始流水 |

单据额度按原首次登记量累计，后续领料不能降低已打印数量；库存额度按**完整Code**汇总余额，并取最新流水关联Goods判断当前位置，不能从Code中的首次数量推算余额。原页面进度已识别017写入的 `labelPrintSource`，用单据类型、主表ID和明细ID准确对应。

两个入口在新表事务内按完整库存身份排序加锁，防止本系统并发预约。库存入口扣除旧当前余额、所有相关待打印占用及尚未进入旧快照的本地余额。已有存货打印标签无法归属到具体单据时，单据入口保守拒绝重复建标，提示核对原标签。外部PDA独立并发写入与库存变化仍属跨系统快照边界，尚未做全部并发矩阵，不能将本轮用例等同于所有生产场景验收。

单位按888物料主计量单位编码校验；历史业务存储的单位名称通过888计量单位档案匹配。发现原业务待打印目标而身份/属性不一致时必须拒绝，不能回退为新建另一组标签。拆包保留原日期和扩展属性；不同原始属性禁止合并拆包。

原首打任务仅在当前打印作用域内直接复用。历史标签若只有旧作用域的任务，不跨作用域读取旧归档或沿用旧设备；在当前作用域核验旧三表首打依据并绑定重建模板/当前设备，基线持久保存，再按原Code补打。历史基线预览使用预览条码，不分配新Code；实际补打冻结原Code和原始数量。

## 现有017结构与新增接口

本轮**没有迁移、建库或放宽表约束**。复用 `business_operation`、`business_operation_line`、`product_label`、`inventory_flow`、事件、任务、编码登记与模板版本等既有结构：

- 来源操作类型 `LABEL_SOURCE`，操作号 `PS-<请求UUID>`；请求摘要不一致返回冲突。
- 来源明细 `source_line_id` 使用 `PS:<来源SHA256>`（已分配）、`PR:<来源SHA256>`（未分配余量）、`PF:<来源SHA256>`（拆包转出）；真实ERP明细保存在 `erp_line_id`，不混用PRINT输出标记。
- 新建来源行不设置扫描选择类型；拆包转出行沿用合法 `LABEL_SCAN` 并保存数量快照。不增加表约束不允许的选择枚举。
- 无Code的原目标拆包后余额为0，因现有Code约束保留 `PENDING_PRINT`，从正余额待打印列表排除；不伪造Code，也不强行改成SPLIT。
- `POST /api/labelsystem/source-print/bill|stock`：独立后端核验并转接 `POST /api/v1/print/source-targets`（服务间签名）。仅当前精确888模拟环境启用。
- `GET /api/labelsystem/source-print/reprint?query=...`：原完整Code或唯一SN查找；`GET /api/v1/print/labels/{id}/original` 取首次冻结快照或已核验的历史首打基线。
- `GET /api/labelsystem/designer-templates/{id}/published`：确认设计稿与已发布版本摘要一致；修改后未重新发布不可发送。
- 首打、补打、授权、回执、重试同步等沿用既有017接口。服务间校验密钥仅保存于两端私有配置，不向页面或文档输出。

## 实测结果

使用实际Edge DOM与真实开发HTTP/SQL，未拦截浏览器业务响应、未读取页面截图，发送仅服务端Go模拟驱动。

- 原单据页：`DBD26103206` 数量2，按1拆成两张，首打完成；原补打页补打其中一张2份，原Code/纸面数量/余额不变。
- 原存货页：同一库存余额1，分四次各0.25，分别验证正常、丢发送回执、丢登记响应和三表登记失败一次。恢复只查询原回执/原同步，重复签名回执不改变计数。四个标签各只有一个Code、一次本地首打和一条旧初始正流水；全部 `PRINT/REPRINT` 数量变化合计0。
- 来源同请求重放返回原目标；额度用尽后新请求409；旧写接口保持409，未经独立后端签名的来源接口不能由普通代理调用。
- 历史标签在当前作用域核验后，刷新保留基线、预览实际生成PDF；再从原补打页模拟补打1份，原纸面数量100、余额35、Code不变，旧初始正流水仍1条。最终在720px视口复查存货选择、模拟队列和额度拒绝；原记录的补打按钮回到同一补打页面；没有本机物理助手请求。
- 单位兼容及部分拆包的真实SQL合成用例：原数量10（使用单位名称），本次3+3+1，余量3；原目标变0，子目标总量10、拆包净变化0，重放同操作，Code登记数量不变。此项为明确合成开发来源，未伪称真实U8业务单据。
