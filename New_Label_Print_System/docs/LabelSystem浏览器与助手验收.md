## 编码与模板核对

开发库原规则 `INV008_STANDARD` 是 `INVENTORY_OBJECT` 类型，并限定账套 `008`。它在开发库中的内容和行版本保持原样；没有连接或修改生产 008。当前首打接口只接受 `PRODUCT_LABEL`，因此不能把原规则直接绑定为 888 当前打印规则。

本轮通过已有规则接口建立 `INV888_PRINT_DEVELOPMENT`（规则 ID 7），复制原有效格式，仅把对象类型改为 `PRODUCT_LABEL`、账套限定及校验改为 `888`；在页面预览、生效并设为当前。原三条 `ACPT_...` 合成规则继续停用，不作为员工测试规则。

格式为 `888|料号|批号|首次数量|10位唯一值`，保留原规则的大小写、分隔符、数量 **2 位小数** 和 10 位唯一值约束。样例预览 `888|DEMO-888|B001|100.00|2609270062` 中的唯一值是输入样例，**不代表正式编码按日期生成**。正式唯一值由 Business API 事务内分配并补足 10 位，同一打印命名空间/环境/账套跨版本共享单调流水下界，不按日或年重置。正式完整码须不超过 100 字符。

若来源数量超过两位小数、料号/批号组合过长，当前规则可能无法用于首打。代码会拒绝损失数量精度或不兼容的完整码，并回滚取号事务；不能静默四舍五入。本轮沿用现有规则精度，未擅自把所有业务规则改为六位小数。需支持这类来源时，应另行调整开发规则版本并重新验收。

现有设计草稿 3 个、正式模板 4 个、版本 5 个、图片资产 2 个。模板均为 76.2×50.8 mm；其中 `DEVPRINT-...` 两个正式模板是此前验收保留证据。实际复测模板 2 / 版本 2：完整 Code 用于二维码，图片资产和文本变量沿用已发布规范化快照。再次发布没有增加版本或资产，也没有发正式 Code；未以截图验证肉眼版式、实际扫描质量或纸张偏移。

## 浏览器模拟发送及恢复

另外在同一份已部署页面中，使用浏览器请求拦截模拟全部打印业务 API 与助手请求，测试页面按钮和状态流转。**模拟能力开关仅存在于该测试浏览器的响应中，公共配置未打开，实际助手不接收发送请求，这部分不作为本轮真实 SQL 写入证据。**

| 场景 | 页面行为与断言 |
| --- | --- |
| 首打后补打 2 份 | 页面准备、模拟发送、完成，再按完整原码查询和补打；补打显示原始数量 100、当前余额 35，原码不变；两项模拟任务合计 2 次模拟发送 |
| 助手响应丢失，恢复登记响应再丢失 | 发送后保留原任务/attempt；“查询任务”后“恢复原任务登记”仅 GET 原助手回执，再提交原回执；模拟提交已完成但响应丢失后再次查询显示完成，不能再发送。全程只有 1 次模拟发送、1 次原回执查询、1 个模拟登记事件 |
| 三表登记失败 | 页面显示“追溯登记待恢复”，“恢复原任务登记”只调用原任务 `retry-sync`；1 次模拟发送、1 次同步重试，恢复不访问助手 |

数据库防重结论继续由此前真实 SQL 验收支撑：首打及重复回执不重复登记，补打流水数量为 0，三表失败恢复使用原事件和 UUID，不再调用驱动。本轮浏览器测试补齐了实际页面操作证据，没有用浏览器内模拟替代真实数据库事务验证。
