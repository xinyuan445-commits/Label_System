# 本地部署与159来源

更新日期：2026-10-20。

当前打印系统采用本地部署。每台打印电脑运行自己的网页和打印助手，159只提供开发业务数据与统一打印账。

```text
本机浏览器
  └─ 127.0.0.1:18003  独立打印网页、模板草稿和素材
       ├─ 172.16.1.159:9891  Label system账号、权限、正式模板、编码、任务和回执
       └─ 172.16.1.159 / UFDATA_888_2021  单据、库存及迁移期TraceBack只读来源

本机打印助手 127.0.0.1:9110
  └─ 本机PDF或打印机驱动
```

本地18003只监听`127.0.0.1`，不开放局域网入站端口。Label system HTTP来源必须与私有配置中的固定来源完全一致；当前为`http://172.16.1.159:9891`，不能在页面中切换到其他服务器。888继续是当前开发账套，生产008未纳入本地打印接入。

## 安装与启动

管理员先构建不含凭据的本地包。构建目录会同时得到ZIP和`Install-LabelSystemLocal.ps1`：

```powershell
.\deployment\Build-LabelSystemLocal.ps1 -OutputPath <本地安装包路径>
```

目标电脑需要Python 3.12和SQL Server ODBC Driver 17或18。管理员通过受控方式提供私有设置文件；该文件包含只读U8连接参数和来源签名密钥，不得提交Git或发送到普通日志。安装命令：

```powershell
.\deployment\Install-LabelSystemLocal.ps1 `
  -PackagePath <本地安装包路径> `
  -PrivateSettingsPath <私有设置文件>
```

首次迁移旧草稿和素材时增加`-SeedDataPath <Data目录>`。安装位置默认为`%LOCALAPPDATA%\NewLabelPrintSystem`，数据保存在其`Data`目录。网页和助手不随Windows自动启动；日常双击项目根目录的“启动标签打印系统.cmd”，脚本会启动本地网页和已安装的打印助手，确认服务可用后打开`http://127.0.0.1:18003/bills`。构建安装包时该脚本也会复制到安装包所在目录。重复双击不会重复启动进程，18003或9110被其他程序占用时会停止并提示。PowerShell启动器使用Windows PowerShell 5可识别的UTF-8 BOM编码，避免中文提示导致解析错误。

打印助手仍安装在`%LOCALAPPDATA%\LabelPrintingAssistant`，`server_url`指向本机18003。已有电脑升级时保留设备私钥、配对身份和持久回执；全新电脑先登录本地网页，再从设备页面下载安装助手并完成配对。当前协议版本为0.7.2，迁移或升级网页不重置助手文件。

## 159清理结果

2026-10-20已停止并删除159上的独立网页部署：

- 删除计划任务`NewLabelPrintDevelopment`。
- 删除18003专用防火墙规则。
- 删除`D:\NewLabelPrintDevelopment`及其中历史发布包。
- 159端口18003无监听；原网址不再是入口。
- 保留并验证9891 Business API与9881 Gateway正常运行。
- 迁移的SQLite数据核对一致：模板3、素材1、标签规格8、用户引用2。
- 后续目标电脑安装所需私有设置保存在159的开发配置目录，仅管理员和SYSTEM可读。

本次没有执行数据库迁移，没有创建打印任务，没有调用打印机，也没有读取或修改生产008。正式打印记录、Code、零数量PRINT/REPRINT流水及TraceBack同步仍由159上的Business API和017结构管理，因此网页移动到本地不会建立第二套库存账。

- 159上的打印Business API更新单独使用`Deploy-888PrintApi.ps1`；该脚本不安装或启动独立网页。
