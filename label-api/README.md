# Label System Business API

## 草稿同步、审核、标签规则和用户管理

`0.8.1` 补齐 U8 明确失败与结果未知的状态边界：明确未执行写入的失败结束为 `FAILED` 并释放锁，只有保存调用后无法回查确认的请求保留 `NEEDS_RECONCILIATION`。development 已对测试账套 888 开放九类新增、审核和弃审。
标签系统业务后端。H5 只调用本服务；本服务访问标签数据库，并通过 U8 Gateway 读取或写入 U8。

当前开发版本为 `0.8.5`；IIS 部署版本以部署记录和健康检查为准。

当前完成：

- 应用用户表驱动的 development 管理员和本地密码账号登录、Bearer Token、当前用户、退出、停用复核和 12 小时会话；密码只保存加盐派生值，连续失败会短时锁定。
- 用户 ERP 制单人映射、直接功能权限、出入库类别范围和用户漫游偏好接口；管理员默认允许、普通用户默认禁止，类别查询和预提交执行服务端范围复核。
- 用户管理需要管理员角色或当前会话短时管理权限，提供锁定状态、最后管理员保护、解锁、会话撤销、漫游数据重置和不含敏感凭据的管理审计。
- 普通用户可通过短时管理密码访问管理接口；授权只作用于当前会话，不能绕过业务功能权限。
- 源单和库存对象查询要求携带业务功能编码并由服务端复核；待处理组只有创建人可以续期或取消，管理员可跨用户查看但不能代替操作。
- 草稿 JSON 最新快照、设备心跳、软删除和状态事件；管理员可查看所有已同步草稿与 PDA 最近上报状态，完全离线设备只能显示最后一次上报结果。
- 草稿保留策略保存在全局设置，活跃和已结束记录分别支持按天或永久；后台每 6 小时清理一次到期记录。
- 健康检查、功能目录、功能启停和系统设置接口。
- 按单据保存 `field_input_rules` JSON，供 H5 独立“单据设置”配置表头、表体字段的显示和必填状态。
- 按单据保存 `auto_add_scanned_detail`，控制 H5 扫码后直接入明细或先逐条确认；该设置不改变服务端库存真实性校验。
- 预提交按当前单据的 `field_input_rules` 执行可配置表头必填校验；扩展字段以扁平 JSON 对象进入操作前归档，单次表头或单行最多 128 项、64 KiB。
- U8 出入库类别、仓库、仓位和部门同步，服务器本地缓存、同步状态和缓存查询接口。
- 产品标签、托盘及托内产品查询，返回最新库存单位、位置、名称快照、状态和行版本。
- 标签 Code 规则能力、管理员草稿维护、启用/停用、目录下发、预览与解析；支持常用一维码、QR 及常用二维载体、自定义分隔符、业务字段、日期、流水和校验位。
- U8 生产、采购、销售和委外源单代理；生产订单另提供领料需求。
- 材料出库服务端预提交：未选源单时按实际仓库拆组；选择生产订单时携带完整表头，增加 U8 需求复核、超领校验、源单占用并按生产订单内部 ID 和仓库拆组。
- 采购到货、委外到货、采购入库、发货单和销售出库预提交：源单可选；选择后增加 U8 源单行复核、同料数量分配、源单占用并按来源单据拆组。
- 调拨、货位调整和盘点预提交：最新库存位置复核、整件/整托校验、幂等和并发锁。
- 九类单据 ERP 新增请求映射、Gateway 校验、回查和本地事务收口；采购到货、委外到货、采购入库和发货单不重复改变现有标签余额，销售出库按方向改变余额，调拨/货位调整写零数量位置流水，盘点按实盘数调整余额。
- 单据基础档案同步与查询：采购类型、销售类型、币种和最新可用汇率；调拨、盘点分别复核出入库两种类别。
- 取消和续期接口，仅用于旧组恢复和运维核对。
- 按单据类型、状态、操作人和日期查询业务组，返回拆组状态、ERP/审核状态、锁时间、异常及汇总；本地缓存清除后仍可恢复已预提交记录。
- 操作前 TXT 凭证。

当前 development 的 `U8WritesEnabled=true`，仅连接测试账套 888。九类单据直接提交会进入真实 U8 新增和回查；正常 H5 流程不再生成供用户二次执行的 `PENDING`，只有旧组恢复仍使用查询、执行、续期和取消接口。

H5 面向用户统一使用“上传 ERP”，不显示“预提交”技术名词。Gateway 只在 888 开放新增、审核和弃审；修改和删除继续关闭。每类单据仍需逐笔完成新增、回读、失败恢复、审核和弃审验收。

支持红蓝字的 H5 单据会提交 `documentDirection=BLUE|RED`。Business API 已把红字标志和数量方向映射到各自 U8 新增请求；当前只允许在 888 逐类验证，未经验收不得切换到生产账套。

规则解析同一规则优先当前启用版本，再回退历史版本；不同规则按较小优先级值优先，同优先级同时命中返回歧义。账套字段校验失败优先返回 `ERP_ACCOUNT_MISMATCH`。当前规则目录可供 H5 缓存，但离线解析、正式发码、流水消耗和统一 Code 登记留待下一阶段。

development 已启用 `INV008_STANDARD` V1：产品和托盘共用 `008|料号|批号|数量|10 位标签唯一值`，数量严格两位小数。账套限定 `008` 是标签业务值，不修改 U8 测试账套 `888`。test 和 production 只安装结构，不复制该规则。

托盘功能暂缓：托盘只作为容器，托内物料必须全部有独立产品标签；未来装托和拆托逐张扫码并以有效托盘关系下的产品标签余额合计作为实时数量。托盘 Code 数量仅作装托快照，内容变化后的换码策略尚待确认。

H5 九类非审核单据现已接入本服务的标签/托盘、服务端草稿和统一单次提交入口。有源单单据统一由本服务代理 U8 Gateway。扫码事件可以由浏览器桥模拟，但库存对象始终来自本服务，模拟标签和模拟正式提交已关闭。

IIS 部署约定和脚本见 `docs/IIS_DEPLOYMENT.md`，本次实际部署记录见 `docs/DEPLOYMENT_2026-10-11.md`。服务器使用版本化发布目录，外置配置和操作凭证不随程序版本覆盖。

当前 development 会话保存在 API 进程内，应用池重启后已有令牌失效。H5 必须使用登录响应返回的令牌访问受保护接口，并在 `401` 后清除本地会话；正式用户体系接入时保持现有接口合同。

## 配置

仓库内 `appsettings.json` 不保存密码。部署时通过环境变量或外部 JSON 配置：

```text
LABELSYSTEM_CONFIG_PATH
ConnectionStrings__LabelSystem
U8Gateway__ApiKey
ASPNETCORE_URLS
```

开发数据库连接 `LabelSystem_Dev`，测试连接 `LabelSystem_Test`，生产连接 `LabelSystem_Prod`。当前按项目决定使用 `sa`，密码只保存在服务器配置中。

## 本地运行

```powershell
dotnet restore src\LabelSystem.Api\LabelSystem.Api.csproj
dotnet run --project src\LabelSystem.Api\LabelSystem.Api.csproj
```

启动前必须提供标签数据库连接串和 U8 Gateway API Key。接口合同见 `docs/API_DESIGN.md`。

## 约束

- 所有业务时间使用北京时间。
- 浏览器不能取得 U8 Gateway API Key 或数据库密码。
- test、production 不允许 `admin/admin` 本地登录。
- 相同 `clientRequestId` 和相同请求内容返回原结果；相同编号提交不同内容返回冲突。
- 锁超时只提示异常，不自动抢锁。没有进入 U8 的待处理操作可通过取消接口释放。
- 九类单据已补齐操作凭证校验、U8 回查、本地事务提交和异常待核对状态；Gateway 新增、审核和弃审已对 888 开放，材料/销售数量单据的托盘执行仍未开放。

`0.8.3` 允许本人草稿从“全部拆组均为明确失败、没有 ERP 单号且没有库存流水”的旧业务组重新绑定到新的重试组，并把全组 `FAILED` 的服务端草稿保持为“未提交”。H5 对明确 `FAILED` 结果保留在“未提交”，每次人工重试生成新的、最长 64 字符的请求号；网络结果不明确时沿用当前请求号查询，避免重复单据。`NEEDS_RECONCILIATION` 仍禁止重试。

`0.8.4` 补齐参照生产订单的材料出库单表头工单号：写入 `iproorderid` 的同时写入 `cmpocode`，表体生产订单和子件需求关联保持不变。

`0.8.5` 开放九类单据“上传自动审核”：先确认 ERP 新增并提交本地库存流水，再使用新增返回的单号和版本执行审核。审核明确失败保留为 `PENDING_APPROVAL`，不允许重新新增；审核结果未知进入 `NEEDS_RECONCILIATION`。H5 可在待审核记录上继续审核。

2026-10-13 材料出库端到端验证已通过：同一生产订单按仓库拆成 U8 单据 `CLCKD20263349` 和 `CLCKD20263350`，业务组成功后写入 3 条 `MATERIAL_OUTBOUND` 流水并释放全部标签锁。两张 U8 单据保持未审核，符合 `autoApprove=false`。
